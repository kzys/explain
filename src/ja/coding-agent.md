# コーディングエージェントについての雑多な感想

昔々、私は「LLM にコードを書かせましょう」という話に懐疑的だった。

Stable Diffusion みたいな画像を生成するのは、結果が1バイトずれてもなんとかなるかもしれない。プログラミングというのはそのずれが文法エラーになって止まる世界なわけで、それは向いているんだろうか?

調べてみると、GitHub Copilot が2021年、ChatGPT, Stable Diffusion が2022年だった。当時の LLM はそこまで賢くなかったし、私の評価基準も「ワンショットでコードは書けないよね」というところにあったと思う。

そこから2025年に Claude Code が出て、「文法エラー」みたいな高速で決定的なフィードバックを LLM にそのまま入力して直させること、LLM 自体の全体的な進化とプログラミングへの最適化が相まって、2026年のいまは「プログラミング、向いてないどころか滅茶苦茶に得意だな」というところにいる。

私もはじめは「メインのコードは自分で書いて単体テストは LLM に書かせる」とか「プルリクエストの説明文は意図を書くところだから人間が書こう」とか、いろいろ線引きを試行錯誤していたのだけど、最近はメインのコードもプルリクエストも LLM に任せてしまっている。

## 趣味プログラミングは簡単になってうれしい

趣味のプログラミング、例えば、会社のオフサイトがあるから、[名刺代わりに DEFCON でやってるようなバッジを作ろう](https://github.com/kzys/chicago)とか、[RG35XX Plus](https://anbernic.com/products/rg35xx-plus) というレトロハンドヘルドを買ったから、[ソフトウェアキーボード](https://github.com/kzys/lowkey/)を作ってターミナルを使えるようにしよう、みたいなことは簡単にできるようになってうれしい。

ここらへんのコードに関しては、差分も読んだり読まなかったりで、結構バイブコーディングしてしまっていることがある。

20代だったら土日をつぶしてやるような趣味のコンピューティングが、平日の夜くらいのパワーでもできるようになったのは、中年にとってはありがたい。

## 仕事のプログラミングはつきあいかたが難しい

一方で、仕事のプログラミングは、そこまで簡単になった感じはしない。

単位時間あたりにできる仕事の量は増えたけれど、結局のところ、9時から5時の間にもっと仕事を詰め込んでいるだけというのもあるし、趣味で書いているものよりは、ちゃんと品質を気にしているので、レビューに時間や神経をとられがち、というのもある。

## ある種の仕事をする人々は減っていく

これは AI に限った話ではないのだけど、私がミクシィで働きはじめたころには、データセンターにサーバーをラックするとか、そこからぬけたサーバーを正しく廃棄するという物理的な仕事があったし、日本の大きめの Web の会社には [Sledge](https://github.com/livedoor/Sledge), [Ridge](https://github.com/hatena/Ridge), [MobaSiF](https://dena.com/jp/news/723/) みたいな自社フレームワークを作るという仕事もあった。

こういう仕事、パブリッククラウドがあり、Rails や Django みたいな定番フレームワークがある現代では、総量としては減ってしまっているのではないかと思う。

フレームワークとかミドルウェアと呼ばれるような、アプリケーションドメインから遠いソフトウェアは、だんだん集約されていって、そのために雇用される人は減っていく、と私は思っている。

ソフトウェア開発をする人間が減るかどうかは、ちょっとまだわからない。ただ、我々の知っているかたちの、昔ながらのプログラミングをする人は、総量としては減っていくのかなあと思う。
