# コーディングエージェントについての雑多な感想

昔々、コーディングエージェントが登場しだしたころ、わたしは懐疑的だった。

Stable Diffusion みたいな画像を生成するのは、結果が1バイトずれてもなんとかなるかもしれない。プログラミングというのはそのずれが文法エラーになって止まる世界なわけで、難しくない?

当然、わたしの当時の予測は間違っていたし、さらにいうと「文法エラー」みたいな高速で決定的なフィードバックがある環境は、AI にとって向いているといっても良いと思う。

そこから「単体テストみたいな定型的なものは書かせてもいいかな」「プルリクエストの説明文くらいは自分で書きますよ」とか自分なりの、ここから先は人間の仕事という線を引いていた。でも、最近はどちらも AI にやらせていて、だいぶ人間の仕事が変わってしまったなと思う。

## 趣味プログラミングは簡単になってうれしい

趣味のプログラミング、例えば、会社のオフサイトがあるから、[名刺代わりに DEFCON でやってるようなバッジを作ろう](https://github.com/kzys/chicago)とか、RG35XX Plus というレトロハンドヘルドを買ったから、[ソフトウェアキーボード](https://github.com/kzys/lowkey/)を作ってターミナルを使えるようにしよう、みたいなことは簡単にできるようになってうれしい。

20代だったら土日をつぶしてやるような趣味のコンピューティングが、平日の夜くらいのパワーでもできるようになったのは、中年にとってはありがたい。結果として、ちょっと夜ふかしも増えているけれど。

あるいは、私はいま自宅に Kubernetes クラスタがあるのだけど、このための YAML もだいたい AI に書かせている。Kubernetes は私にとって AI 以後に真面目に触れたソフトウェアのひとつで、あの深いインデントの YAML とか、それを Go のテンプレートで生成するとか、人間にむかない、もとい AI むきの仕事だと思う。そして、この「これは人間にむかないな」というのに、まるっとプログラミング全体が入る人々がいるのもわかる。

## 仕事のプログラミングはつきあいかたが難しい

一方、仕事で使うのは、なかなか難しい。

そもそも、分散システムが多くて、作っているものが複雑というのもあるし、社内の他の人々と協力して、オンコールも持ち回りで運用するものなので、品質についての要求が高い。趣味でつくるものは、こと最近は、単純で雑にやっていることが多い。

あと、9時から5時まで AI の出力をながめていると疲れるというのもある。仕事のゴールは変わっていないのだけど「手触り」みたいなものは大分かわってしまった。ただ、プロンプトひとつで色々やってくれるので、エディタにむかってコードを書くほどの元気がないときでも、ずるずる続けてしまうというのもある。

ここに対人関係に起因する問題や、ハーネスの設定に凝った人々に対する FOMO もあって、ひとえに「うれしい」とはいえない複雑な感情がある。

## ある種の仕事をする人々は減っていく

これは AI に限った話ではないのだけど、私がミクシィで働きはじめたころには、データセンターにサーバーをラックするとか、そこからぬけたサーバーを正しく廃棄するという仕事があり、日本の大きめの Web の会社には [Sledge](https://github.com/livedoor/Sledge), [Ridge](https://github.com/hatena/Ridge), [MobaSiF](https://dena.com/jp/news/723/) みたいな自社フレームワークがあり、アメリカの会社だとここに分散ストレージとかリバースプロキシみたいなミドルウェアが加わる、というのが結構あった。

この感じ、Rails や Django みたいな定番フレームワークがあり、パブリッククラウドが色々なプリミティブを提供する時代の人々には、あまり伝わらないと思う。

フレームワークとかミドルウェアと呼ばれるような、アプリケーションドメインから遠いソフトウェアは、だんだん収斂が進んでいって、そのために雇用される人は減っていく、と私は思っている。経験からくる諦観もあるし、これを逆行させようとすると「国産 OS の雇用の枠はありますが、アプリケーションを作るひともがんばって国産 OS を使ってください」みたいなことになり、あまりうれしくないよね、というのもある。

AI が雇用を奪うというのも、本当にみなが失業して消費者がいなくなる事態にでもならない限りは、いつもの収斂のひとつなのでは、という気持ちがしてしまう。
